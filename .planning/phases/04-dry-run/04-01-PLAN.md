# Plan 04-01: Simulation Engine

## Goal
Build a paper trading engine that simulates order execution without risking real capital. Allows strategy validation before going live.

## Components

### 1. PaperTradingEngine
Main simulation class that replaces real OrderExecutor for testing.

**Features:**
- Mock order execution (no API calls)
- Simulated fills with configurable fill rates
- Queue position uncertainty
- Track paper positions and P&L
- Use real market data for realistic pricing

### 2. SimulationConfig
Configuration for simulation parameters.

```python
@dataclass
class SimulationConfig:
    fill_probability: float = 0.85  # 85% chance of fill
    partial_fill_rate: float = 0.1  # 10% chance of partial
    slippage_bps: float = 5.0       # 5 basis points slippage
    execution_delay_ms: float = 100  # Simulated latency
```

### 3. PaperPositionTracker
Extends PositionTracker for paper trading.
- Separate paper positions from real positions
- Track simulated P&L
- Record all paper trades

## Implementation

### File: `src/services/paper_trading.py`

```python
class PaperTradingEngine:
    async def execute_paper_trade(opportunity: PairOpportunity, size: int) -> PairExecutionResult
    def get_paper_positions() -> List[Position]
    def get_paper_pnl() -> float
    def reset() -> None
```

### Integration
- Same interface as OrderExecutor
- Swap in PaperTradingEngine for dry run mode
- Use real WebSocket data for market prices

## Simulation Logic

### Fill Simulation
1. Check if price is still valid (market hasn't moved)
2. Apply fill probability (85% base)
3. Determine fill amount (full vs partial)
4. Apply slippage if configured
5. Record paper position

### Market Resolution
- When market expires, simulate resolution
- Calculate P&L based on BTC price movement
- Each pair = $1.00 payout regardless of outcome

## Test Script

- Execute multiple paper trades
- Show P&L tracking
