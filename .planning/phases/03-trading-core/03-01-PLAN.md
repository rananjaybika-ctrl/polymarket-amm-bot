# Plan 03-01: Order Placement

## Objective
Implement order placement capabilities with parallel execution for Up/Down pairs to prevent legging risk.

## Background

### py-clob-client Order API
- `OrderArgs(token_id, price, size, side)` - Order parameters
- `create_order(order_args, options)` - Creates and signs an order
- `post_order(order, orderType)` - Submits single order
- `post_orders([PostOrdersArgs])` - **Batch submission** for atomic pair execution
- `cancel_orders(order_ids)` - Cancel orders
- `get_orders()` - Get open orders
- `get_tick_size(token_id)` - Price precision (0.01 for BTC markets)
- `get_neg_risk(token_id)` - Negative risk flag

### Order Types
- GTC: Good Till Cancelled (default)
- GTD: Good Till Date
- FOK: Fill Or Kill (entire order or nothing)
- FAK: Fill And Kill (partial fills ok, cancel remainder)

### Side Values
- "BUY" - Buy tokens
- "SELL" - Sell tokens

## Legging Risk Mitigation

**Problem:** If we submit Up and Down orders separately, one might fill while the other doesn't, leaving us exposed.

**Solutions:**
1. **Batch submission** - Use `post_orders()` to submit both atomically
2. **FOK orders** - Orders must fill entirely or cancel
3. **Conservative sizing** - Only trade size available on BOTH sides
4. **Recovery logic** - If partial fill, immediately exit position
