# Plan 03-04: Trade Logging

## Objective
Implement comprehensive trade logging with CSV export for analysis.

## Background

### Why Trade Logging
- Track all executions for auditing
- Calculate performance metrics
- Identify patterns and optimize strategy
- Compliance and record-keeping

### Data to Log
- Timestamp
- Market (slug, question)
- Side (UP/DOWN)
- Action (BUY/SELL)
- Price, Size
- Order ID
- Fill status
- P&L (realized/unrealized)
- Session info

## Implementation

### Step 1: TradeLog Model
Create `src/models/trade_log.py`:

**TradeEntry dataclass:**
- timestamp: datetime
- market_slug: str
- side: str (UP/DOWN)
- action: str (BUY/SELL)
- price: float
- size: float
- cost: float
- order_id: str
- fill_status: str
- pair_id: Optional (links Up/Down in pair)
- session_id: str
- notes: str

**PairTradeEntry:**
- Groups Up and Down trades
- Calculates pair cost and profit

### Step 2: TradeLogger Service
Create `src/services/trade_logger.py`:

**Core Methods:**
- `log_trade(entry)`: Add single trade
- `log_pair_trade(up_entry, down_entry)`: Add pair
- `get_trades(filters)`: Query trades
- `get_pair_trades()`: Get grouped pairs

**Export Methods:**
- `export_csv(filepath)`: Export all trades
- `export_pairs_csv(filepath)`: Export pair trades
- `export_summary_csv(filepath)`: Export daily summary

**Statistics:**
- `get_daily_stats(date)`: P&L, volume, win rate
- `get_session_stats(session_id)`: Per-session metrics
- `get_total_stats()`: All-time metrics

### Step 3: Integration
- OrderExecutor calls `logger.log_pair_trade()` on fills
- PositionTracker updates use logger
- Session start/end logged

### Step 4: CSV Format
```
timestamp,market,side,action,price,size,cost,order_id,pair_id,session_id
2024-12-19 10:30:00,btc-updown-15m-123,UP,BUY,0.51,10,5.10,ord-abc,pair-1,sess-1
2024-12-19 10:30:00,btc-updown-15m-123,DOWN,BUY,0.51,10,5.10,ord-def,pair-1,sess-1
```
